# الدليل التشغيلي لـ Styloraify

## 1. المتطلبات

يتكون النظام من ثلاث خدمات يجب تشغيلها ضمن شبكة موثوقة. يحتاج خادم Laravel إلى PHP وComposer وقاعدة بيانات متوافقة مع إعدادات `backend-laravel/.env`، وتحتاج الواجهة إلى Node.js وnpm، فيما تحتاج خدمة الصور إلى Python وبيئة افتراضية مستقلة. لا تستخدم قاعدة SQLite المرفقة في الأرشيف كقاعدة تطوير أو إنتاج؛ هي حالة محلية مولدة، وتبقى migrations وseeders هي المصدر المعتمد للمخطط.

| الخدمة | متطلبات التشغيل | ملف الاعتماد |
|---|---|---|
| Laravel | PHP المتوافق مع [`composer.json`](../backend-laravel/composer.json)، Composer، وقاعدة بيانات | `backend-laravel/composer.lock` |
| React | Node.js وnpm | `frontend/package-lock.json` |
| FastAPI | Python 3 وبيئة افتراضية | `backend-laravel/image-ai-service/requirements.txt` |
| موفر الصور | حزمة/خدمة موفر التوليد وبيانات اعتمادها | عقد `emergentintegrations` المستخدم في `image_generator.py` |

## 2. إعداد البيئة

أنشئ ملف بيئة مستقلًا لكل خدمة، ولا تستخدم ملفًا مشتركًا أو تضع بيانات اعتماد داخل الواجهة. القيم الآتية توضح العقد التشغيلي، لا قيمًا جاهزة للإنتاج.

| الخدمة | المتغير | الوصف |
|---|---|---|
| Laravel | `APP_ENV` و`APP_KEY` و`APP_URL` | إعداد التطبيق ومفتاح التشفير وعنوانه العام. |
| Laravel | `DB_*` | الاتصال بقاعدة البيانات المختارة. |
| Laravel | `AI_SERVICE_URL` | عنوان FastAPI الداخلي؛ راجع `config/services.php`. |
| Laravel | `INTERNAL_SERVICE_KEY` | قيمة سرية تطابق خدمة الصور لحماية طلبات التوليد. |
| React | `REACT_APP_BACKEND_URL` | أصل Laravel في بيئة الواجهة. |
| React | `REACT_APP_API_URL` | أصل API عند استدعائه من وحدات العميل. |
| React | `REACT_APP_GOOGLE_CLIENT_ID` | معرف عميل Google OAuth العام، مع ضبط authorized origins. |
| FastAPI | `INTERNAL_SERVICE_KEY` | نفس السر الموجود في Laravel عند تفعيل التحقق الداخلي. |
| FastAPI | `ALLOWED_ORIGINS` | قائمة origins مفصولة بفواصل؛ قيدها على واجهة الإنتاج. |
| FastAPI | اعتماد موفر الصور | مفتاح/إعداد المزود في بيئة الخدمة فقط. |

> **قاعدة أمان:** متغيرات `REACT_APP_*` تُضمَّن في bundle ويمكن قراءتها من المتصفح. لا تضع API keys أو كلمات مرور أو أسرار داخلها مطلقًا.

## 3. تشغيل التطوير

نفذ الخطوات داخل كل دليل مخصص. استخدم نافذة أو خدمة منفصلة لكل عملية؛ لا تبدأ خادم الصور من عملية React أو من web worker عشوائي. قبل أول تشغيل للخلفية، راجع إعدادات قاعدة البيانات، نفذ migrations، وأنشئ بيانات تجريبية مقيّدة لبيئة local فقط.

| المكوّن | التسلسل المقترح |
|---|---|
| Laravel | ثبّت اعتماديات Composer وفق lockfile، انسخ قالب البيئة في بيئة محلية، اضبط `APP_KEY` وDB، شغّل migrations/seeders، ثم ابدأ Laravel. |
| React | داخل `frontend/` نفّذ `npm install`، اضبط متغيرات `REACT_APP_*`، ثم استخدم `npm start`. |
| FastAPI | أنشئ virtual environment، ثبّت المتطلبات، وفر حزمة موفر الصور المعتمدة، ثم شغّل Uvicorn على شبكة محلية أو خاصة. |

لا يكتمل تشغيل التوليد الحقيقي حتى تتوفر حزمة `emergentintegrations` أو بديلها المتوافق وبيانات اعتماد موفر الصور. لا تتجاوز هذا القيد بتعطيل التحقق الداخلي أو بوضع مفتاح مزود داخل الكود.

## 4. بناء الواجهة والنشر

ينتج `npm run build` ضمن `frontend/` مجلد `build/` للنشر الثابت. لا ترفعه إلى Git؛ هو مخرج قابل لإعادة البناء ومُستبعد في قواعد Git. انشره على CDN أو خادم static، واضبط متغيرات البيئة قبل عملية build؛ Create React App يقرأها وقت البناء لا بعده افتراضيًا.

| بيئة النشر | الإجراء الضروري |
|---|---|
| التطوير | السماح لـReact على localhost بالاتصال بعنوان Laravel المحلي، مع FastAPI داخل شبكة التطوير. |
| الاختبار | استخدام قاعدة بيانات ومفاتيح OAuth ومزود صور مستقلة، وتفعيل سجلات تشخيص دون بيانات مستخدم حقيقية. |
| الإنتاج | HTTPS، reverse proxy، CORS مقيد، FastAPI غير مكشوف مباشرة للعامة، وبيانات اعتماد تدار عبر خدمة أسرار. |

## 5. FastAPI وخدمة الصور

تشغل الخدمة endpoint للصحة وendpoint للتوليد. يمر الطلب من Laravel إلى الخدمة مع سر داخلي حين يكون مفعّلًا. لا تسمح للعميل العام باستدعاء endpoint التوليد مباشرة في الإنتاج، لأن Laravel هو المكان المناسب لتطبيق الحصة والمصادقة وربط التصميم بالمستخدم.

| عنصر تشغيلي | التوصية |
|---|---|
| المنفذ | استخدم المنفذ المرجعي 8002 داخل شبكة خاصة أو عرّفه عبر proxy. |
| CORS | حدد origins صريحة؛ لا تستخدم wildcard مع cookies أو credentials. |
| حجم الصورة | طبّق حدودًا في proxy وLaravel وFastAPI على payload Base64 لتفادي استنزاف الذاكرة. |
| المهلات | ضع timeout معقولًا في Laravel عند الاتصال بالخدمة، وسجل فشل المزود دون كشف prompt أو token. |
| التخزين | استخدم تخزينًا مراقبًا للصور الناتجة بدل الاحتفاظ ببيانات Base64 كبيرة في كل سجل إن نما الاستخدام. |

## 6. الاستعادة والنسخ الاحتياطي

نسخ قاعدة البيانات وملفات الوسائط الناتجة وسجلات الإعدادات السرية مسؤولية تشغيلية منفصلة عن Git. اختبر الاستعادة دوريًا في بيئة منفصلة. يجب أن تشمل خطة التعافي lockfiles وملفات النشر ونسخة من migrations، إضافة إلى بيانات قاعدة الإنتاج والوسائط التي لا ينبغي حفظها ضمن المستودع.

| الأصل | أسلوب الحماية |
|---|---|
| قاعدة البيانات | نسخ مشفر ومؤرخ واختبار استعادة دوري. |
| أسرار OAuth وموفر الصور | مدير أسرار مع تدوير ومبدأ أقل صلاحية. |
| وسائط التصميم | storage منفصل مع سياسة وصول واحتفاظ ونسخ احتياطي. |
| lockfiles | تبقى في Git لضمان إعادة بناء متسقة. |
| سجلات الأخطاء | تجميع مركزي مع تنقية tokens ومحتوى الصور والبيانات الشخصية. |

## 7. فحوص ما قبل الإنتاج

قبل الإطلاق، تحقق من تقييد CORS، صلاحيات الإدارة، عزل المستخدمين عند قراءة التصميمات والطلبات، وصحة تخفيض/استعادة الحصص. نفذ اختبارًا موثقًا يمر من الواجهة إلى Laravel ثم FastAPI باستخدام حساب ومفتاح مزود اختبار. تحقق من فشل آمن عند غياب `INTERNAL_SERVICE_KEY` أو مفتاح المزود أو Google client configuration، ولا تحول هذه الأخطاء إلى نجاح صامت.

راجع [`VERIFICATION.md`](VERIFICATION.md) لحالة الاختبارات التي أجريت على هذه النسخة وحدودها الفعلية.
